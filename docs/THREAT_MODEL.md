# Threat Model

## In scope

- Social-engineering language designed to trigger fear, urgency, isolation, secret disclosure, payment, remote access, or impersonation.
- Malformed, oversized, or unsupported audio uploads.
- Misleading confidence from a single voice signal.
- A score-only response that cannot explain the active coercion or the safest independent verification route.
- Privacy risk from persisting raw call recordings.

## Defensive controls

- Audio allowlist and a 25 MB hard input limit.
- Path filename sanitization and an ephemeral TemporaryDirectory; no raw audio is stored by the app.
- JSON-only API, body-size limit, static-file traversal restrictions, and restrictive response headers.
- No shell command receives user-supplied file paths except fixed temporary paths generated by the server.
- Model artifact is JSON, not an untrusted pickle.
- Logs contain event metadata and aggregate outcomes, never audio or transcript text.
- Fusion requires conversation behavior; synthetic voice alone contributes a capped 8 points.
- The Threat Narrative Graph is bounded by existing session limits, preserves timestamped tactic provenance, and exposes counterfactual evidence rather than a caller-identity assertion.
- The Counter-Pressure Protocol never contacts a caller, financial institution, authority, or reporting portal automatically.
- Incident exports exclude raw text and redact likely credentials and identity values by default; local feedback and novelty monitoring retain aggregate, content-free data only.
- The Threat Narrative Graph uses a versioned evidence/tactic/playbook schema so another local component can inspect provenance without receiving a whole transcript.

## Out of scope

- Telephony interception, payment reversal, automated police reports, caller identity verification, forensic evidence preservation, and malware analysis.
- An adversary can evade phrase detection using paraphrase, another language, noise, coded language, or a genuine emergency narrative.
- Browser microphone privacy and permissions remain under the browser/OS security model.
- Capturing protected third-party call audio, bypassing platform permissions, or silently operating during a call is not an acceptable SCAMTRACE integration strategy.
